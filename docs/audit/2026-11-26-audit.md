# ClubCatan audit — 2026-11-26

Scope: full read of `main` (67 commits), local install, build, test run, engine probes, a two-client WebSocket smoke test against `partykit dev`, and a check of the live deployment and hosting platform. No real-device or Lighthouse testing was done.

Goal this audit serves: host the game indefinitely for a friend group as a colonist.io replacement. Fast, phone-friendly, does not break.

## Bottom line

1. **The game is currently offline and cannot be redeployed as-is.** `clubcatan.piyushd1.partykit.dev` is NXDOMAIN. The hosted PartyKit platform shut down on 23 Oct 2026 and `npx partykit deploy` no longer works ([shutdown notice](https://blog.partykit.io/posts/hosted-platform-shutdown/)). `deploy.yml` will fail on the next push to `main`. The supported path is PartyServer on your own Cloudflare account via `wrangler` ([migration guide](https://docs.partykit.io/guides/migrate-to-partyserver/)). The migration guide describes it as a small diff for most projects.
2. **Game state lives only in memory.** `party/server.js` never touches `room.storage`. A Durable Object restart (deploy, eviction, platform hiccup) deletes the game. The client already has a code path for this: "Your expedition ended while you were away." For 60–90 minute games this is the top "it broke" risk after hosting.
3. **The server trusts the client.** 13 authority gaps confirmed by running the engine (details below), including out-of-turn building, free roads during the main game, negative trade/discard amounts, and `NaN` corruption of resource counts. Among friends the risk is less cheating than a stale or double-tapped client corrupting a game nobody can recover.
4. **The rules engine, protocol and UI shell are otherwise in good shape.** 2.3k-line engine ported from Viral-Doshi/catan, 282 passing assertions across 7 suites, clean JSON-envelope protocol with acks, Preact + Vite + Tailwind client at 48 KB gzipped JS, working PWA manifest/service worker, IndexedDB snapshot cache, wake lock. The local dev server boots and the create → join → start → place flow works over real WebSockets.

## Findings

### Blocker

**B1. Hosting platform is gone.** See bottom line 1. Everything in `partykit.json`, `deploy.yml`, README "Live" link, and `partykit-client.js`'s `.partykit.dev` assumptions (also the service-worker `NetworkOnly` rule for `*.partykit.dev`) must move to a Worker you own. Nothing to migrate data-wise since no room storage was ever used.

### Critical

**C1. No server-side persistence.** `this.game` is a plain field. Durable Objects can be evicted at any time; a `wrangler deploy` mid-game also kills every room. Fix is small: write `game` to `ctx.storage` after every successful mutation, load it in `onStart`, and the existing `reconnect` flow will then survive restarts. Also consider `hibernate: true` so idle rooms cost nothing and survive.

**C2. Server authority gaps (all confirmed with `/tmp/cc-probe.mjs` against the real engine; #2 also confirmed over the wire):**

| # | Hole | Effect |
|---|---|---|
| 1 | `rollDice` has no `phase === 'playing'` guard | Host can roll in the lobby; a 7 puts the lobby into `robber` phase |
| 2 | `placeSettlement` has no turn/phase check | Any player places unlimited free settlements during setup (probe: 5 placed, +5 VP); out-of-turn paid placement in main game |
| 3 | `placeRoad` trusts client-supplied `isSetup`/`lastSettlement` | `isSetup: true` during the main game = free roads forever |
| 4 | `placeRoad` has no turn/phase check | Build out of turn or before rolling |
| 5 | `discardCards` accepts negative amounts | `{brick:5, lumber:-1}` passes "exactly 4" and nets +1 lumber |
| 6 | `proposeTrade` accepts negative offers; `respondToTrade` doesn't re-check offerer stock | Offerer gains resources; victim goes negative; or offerer spends offered goods before accept → negative balance |
| 7 | `yearOfPlentyPick` doesn't validate resource name | `resources.gold = NaN`; every total becomes `NaN` |
| 8 | Monopoly doesn't validate `params.resource` | Same `NaN` corruption, card consumed |
| 9 | `moveRobber` doesn't check victim has a building on the hex | Steal from anyone, anywhere |
| 10 | No `phase === 'finished'` guard anywhere | Game continues after a win |
| 11 | `advanceSetup` doesn't verify 1 settlement + 1 road were placed | Setup can be skipped or doubled |
| 12 | `playDevCard` has no `turnPhase` check | Knight playable during `discard`/`robber` phases |
| 13 | `bankTrade` doesn't validate `getResource` | `NaN` corruption |

Root cause is structural: the engine was written for a trusted single-process server and the client UI gates everything. The fix is one validation layer in `server.js` (or at the top of each engine mutator): phase/turn ownership from server state, never from payload; resource keys from a whitelist; amounts as non-negative integers; `isSetup` derived from `game.phase`.

### High

**H1. Touch targets are far below the design target on phones.** Computed from `hex-math.js` at real viewport widths:

| Board | Viewport | Vertex tap target | Edge tap width | Number token |
|---|---|---|---|---|
| Standard | 360 px | 21 px | 9 px | 22 px |
| Standard | 390 px | 23 px | 10 px | 24 px |
| Extended (5–6p) | 360 px | 16 px | 7 px | 17 px |

The design doc set ≥44×44 px. The two-step Confirm Move softens mis-taps but doesn't fix them. No pinch/zoom is implemented (`@use-gesture/react` is installed and unused; HexBoard comment says "pinch/pan in 1.10c" which never landed). Each physical vertex also has 2–3 overlapping hit discs (one per equivalent key) because the engine stores all 114 keys for 54 physical vertices.

**H2. `gameState` replaces the whole tree on every tick.** `applyServerMessage` does `d.game = msg.state`. The design doc's `mergeSnapshot` for identity preservation was never written, so `memo` on `HexTile`/`Building`/`Road` never hits; every server message re-renders the full SVG (19–30 tiles, 114–174 vertex hit discs, 114–180 edge hits). Preact keeps this tolerable, but it's the first thing to fix if mid-tier Android feels laggy.

**H3. No disconnect visibility or AFK handling.** `playerDisconnected`/`playerReconnected` are no-ops in the store; `game` has no per-player connected flag. If someone drops, the table has no idea and no way to proceed (no turn timer, no skip, no host kick). colonist.io has all three.

### Medium (rules and UX correctness)

- **M1. Robber steal is per resource type, not per card.** Victim with 9 wool + 1 ore loses the ore 49.5% of the time (rules: 10%). Measured over 4,000 trials.
- **M2. Game-over screen never names the winner.** `Board.jsx:339` and `:1476` do `players[game.winner]`, but `game.winner` is a player UUID, so `winner` is always `undefined` → "The game has ended", never "You Won".
- **M3. No bank limits** (19 of each resource). Standard rule; some groups care.
- **M4. No board-balance constraints** (6/8 adjacency, same-number adjacency). Fully random layout. colonist offers balanced boards.
- **M5. Only roll total shown.** `gameStore` stores `msg.roll?.dice` which the server never sends (it sends `die1`/`die2`), so `lastRoll.dice` is always `null`. No dice faces anywhere in the UI.
- **M6. Faction colours cap at 4.** `FACTIONS = ['red','blue','gold','green']` in `Board.jsx` and `Lobby.jsx` → seats 5–6 fall back to red (`?? 'red'`). `HexBoard` has 6 colours, so pips and board disagree for 5–6 players.
- **M7. Trade modal shows for players who already declined** (`Board.jsx:430` doesn't consult `tradeOffer.responses`).
- **M8. Reconnect auth is `playerId` only.** Acceptable for friends (UUIDs are unguessable), but anyone who gets the URL+localStorage can take a seat. Room codes are guessable in principle (29^6 space, no rate limit) — fine for private use, worth a lobby lock once hosting is public.
- **M9. Spectator session doesn't survive reload.** `reconnect` requires a `playerId`; spectators have `null`, so a refreshed spectator lands on the ConnectingCard forever until they Cancel.
- **M10. Setup-phase 2-step commit can desync.** If `placeSettlement` succeeds and the socket drops before `placeRoad`, the client's `settlementCommitted` flag is lost on reload and the player can't see they owe a road; combined with C2 #11 they can `advanceSetup` without one.

### Low (hygiene and drift)

- **L1. 6,916 lines of dead legacy React code.** `client/src/components/*.jsx|css` (ActionPanel, CardReveal, Chat, Confetti, DevCardModal, DiceDisplay, DiscardModal, GameBoard, old HexBoard, InfoPopup, Lobby, PlayerPanel, ResourceCards, RulesModal, TradeModal) are not imported anywhere; four still reference `socket.io`. `App.css` is legacy too. Vite tree-shakes them out of the bundle, but they confuse every reader and every AI agent.
- **L2. 137 unmerged bot branches** (Jules "bolt-*", "palette-*"), mostly duplicate micro-optimisations of `getTotalResources` and aria-label additions. 7 bot PRs were merged. Prune.
- **L3. Leftover hosting configs** from the original fork: `render.yaml` (references a deleted `server/` dir), `client/vercel.json`, `client/static.json`, `client/public/_redirects`.
- **L4. README drift.** Says engine is `party/gameLogic.js` (it's `shared/`), tests are `party/test-*.js` (they're `tests/`), links `DEBUG.md` (only on `debug` branch), "Live" URL is dead, instructs `npx partykit deploy` (dead). `debug` branch is 24 commits behind / 10 ahead of `main`.
- **L5. Dead store state and selectors.** `incomingTrade`, `tradeOffers`, `draftTrade`, `selection` are unused or superseded by `game.tradeOffer`; `selectHexes` reads `game.board.hexes` which doesn't exist.
- **L6. Unused dependency** `@use-gesture/react`. `workbox-window` also appears unused directly (vite-plugin-pwa handles registration).
- **L7. CI runs `test:logic` only**; `test:client` (hex-math, room-code) is skipped in CI.
- **L8. `achievementChanged` handler calls `useGameStore.setState` from inside a reducer** via `setTimeout` — works, but duplicates `pushNotification`.
- **L9. LICENSE** still only credits Viral Doshi 2024; the design doc planned adding a line for this project's contributions.
- **L10. `partykit.json` `compatibilityDate: 2026-04-19`** will need to become `compatibility_date` in `wrangler.jsonc`.

## Gap vs colonist.io for a friend group

Not a feature-parity exercise, just what will make people go back to colonist:

1. Game dies when the server restarts (C1) or a client hiccups (C2).
2. No turn timer / AFK skip / disconnect indicator (H3).
3. Fiddly taps on the board (H1), no zoom.
4. No dice faces, no action log/history, no chat in the live UI (server has `chatMessage`; the new UI never wired it).
5. No board balance option (M4), no bank limits (M3).
6. Nothing to show who won (M2).

Things ClubCatan already does better for a private group: no accounts, no ads, instant share link, installable, hands hidden server-side, 5–6 players included.
